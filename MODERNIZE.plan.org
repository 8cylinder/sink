* Overview
  This is a rewrite of the 2026-09-13 review.  It keeps the parts of the
  original plan that survived verification, corrects the parts that did not,
  and folds in =app-base.org= (the house standard for Python CLI apps) and
  =TODO.org= (the author's backlog).

  The app is ~3,100 lines across 14 modules.  The dominant problems are
  structural, not algorithmic:

  - One mutable global =config= object is simultaneously the data store, the
    loader, and the process-wide singleton.  Everything is an untyped
    =Dict2obj=.
  - All remote work goes through =subprocess(..., shell=True)= with f-string
    interpolation of config and user values, including database passwords.
  - There are no tests, no CI, no lint/format/type configuration, and no
    working development environment: =poetry= is not installed, the committed
    =.venv= is broken, and the tracked =uv.lock= is an unusable stub.
  - Several commands are crash-on-use (=deploy=, =single=, =action local=),
    and dry-run still executes remote tools.
  - Packaging is split between Poetry, a legacy =setup.py=, and a stub lock.
  - The CLI predates the house standard: no =--color=, no =--config=, no
    static completions, no =make= targets, no gitleaks hook, no GitHub
    workflows.

  The hard product requirement is command transparency: every shell command,
  rsync/ssh invocation, and database pipeline is printed in a copy-pasteable
  form, and the printed command is the one executed in that mode.  Dry-run is
  the default: it uses the tool's native dry-run when one exists (=rsync
  --dry-run=) and prints only otherwise.  =--real/-r= prints and executes the
  real variant.  See "Command transparency (core contract)".

  This plan is organized as discrete, sequential stages.  Each stage has a
  goal, a task list, and exit criteria.  No stage starts until the previous
  stage's exit criteria are met, except where noted as parallelizable.

** Command transparency (core contract)
   The printed shell command is the product.  This is not a debug aid; it is
   the reason the tool exists.  Every stage that touches execution must
   preserve it.

   - Build exactly one command object per action *before* doing anything.
     The object is the single source of truth for both display and execution.
   - Default (no =-r=/=--real=): use the tool's native dry-run mode when it has
     one.  Render the dry-run variant, print it, and execute it, so the user
     sees both the command and its intended action.  =rsync= gets
     =--dry-run= and its itemized "what would transfer" output is shown.  If
     the tool has no dry-run mode, render the real command, print it, and do
     not execute it.  The displayed command is always the one that runs in
     that mode, or the exact command =--real= will run when the mode is
     print-only.
   - =--real/-r=: render the real variant (without the dry-run switch), print
     it, and execute it.  The command is still shown; only execution differs.
   - The command object owns both variants: =render(real: bool)= and
     =execute(real: bool)=.  They differ only by the tool's dry-run flag (and
     any tool-specific read-only switch).  There is no second construction
     path that can drift.
   - Dry-run capability is explicit per tool; never pass an invented
     =--dry-run= to a tool that does not support it.
     | Tool                           | Dry-run switch          | Default behavior |
     |--------------------------------+-------------------------+------------------|
     | =rsync=                          | =--dry-run=               | execute it       |
     | =ssh= / =scp=                      | none                    | print only       |
     | =mysqldump= / =mysql=              | none                    | print only       |
     | =git= (diff)                     | none                    | print only       |
     | =pv=                             | none                    | print only       |
     | =lando= / =ddev=                   | none documented         | print only       |
     | remote =mkdir=/=mv=/=ln=/=touch= | none                    | print only       |
     | =sink diff= (needs real rsync)   | =--dry-run= on rsync only | print only       |
     The current =db.py= passes =--dry-run= to =mysqldump=; that is invalid and
     is fixed by this table.
   - =-q/--quiet= hides only the rendered shell command; the command's own
     output (rsync itemized lines, git diff, mysql errors) and the success
     line are still shown.  =--suppress-commands/-s= is the same behavior and
     remains as an alias.
   - =-qq= hides the render *and* the command's stdout/stderr *and* every
     status/success/error line.  The exit code is the only signal; use it in
     scripts.  =--silent= is an alias during the deprecation window.
   - The rendered string must be valid POSIX shell: quote every argument with
     =shlex.join= (or =shlex.quote= for fragments), use absolute paths where
     the shell would otherwise resolve differently, and do not wrap lines with
     backslash-newline unless that is valid shell.  Pasting it into a shell
     must reproduce the executed command.
   - Command kinds:
     - *Argv*: the object stores =list[str]=.  Display is
       =shlex.join(argv)=; execution is =argv= (equivalent to pasting).
     - *Pipeline/redirection*: the object stores stages and redirections.
       Display is =stage1 | stage2 > file 2>&1=; execution is a =Popen= chain
       (or, if that is impossible, one audited =sh -c= of the already-quoted
       render).  The displayed pipeline is the executed pipeline.
     - *Remote*: the object stores the local =ssh= argv plus the remote
       fragment.  Display quotes the fragment as one argument; execution
       passes that exact fragment to the remote shell.
   - Output styling separates the rendered command from its output.  Use the
     current =ui.py= palette as inspiration, but every style goes through
     =rich= (no =click.style= / =click.secho=):
     | Element              | Style                                      | Stream |
     |----------------------+--------------------------------------------+--------|
     | rendered command     | yellow, dim, =+ = leader, wrapped as shell | stdout |
     | command output       | terminal default, unstyled, indented       | stdout |
     | success (real)       | white bold on green, =[Success]= label       | stdout |
     | success (dry run)    | white bold on blue, =[Success (DRY RUN)]=    | stdout |
     | warning              | yellow, =[Warning:]= label                   | stderr |
     | error                | red, =[Error:]= label                        | stderr |
     | notice / information | blue or cyan, =[Notice:]= label              | stderr |
     A blank line separates the command block from its output; a dim rule or
     blank line separates actions.  Never rely on color alone; labels always
     include a word or symbol.
   - Secrets are never rendered into the command.  The object carries the
     secret out-of-band (environment or a =0600= credentials file), and the
     display shows the environment reference or file path, not the value.
     The executed command therefore matches the display; copy-paste works when
     the same environment/credentials are present.  =--show-secrets= is an
     explicit, documented escape hatch for debugging, never a default.
   - Every stage verifies the contract with a test: render the object, split it
     back with =shlex.split= (or run it in a stub shell), and assert it equals
     the argv/pipeline that would execute.  Golden tests pin the exact text for
     =file=, =db=, =deploy=, =check=, and =diff=.

** Test-first workflow (required from Stage 3 onward)
   The goal is to prove a test failed before the fix, while keeping every
   commit bisectable (no red commits in history).

   1. Write the test from this plan, =TODO.org=, and the public CLI contract,
      not from the implementation.  Assert public behavior: exit code, output,
      generated command text, and files created/not created.

      =make check= stays green because the failure is expected.
   3. *Red proof*: run the new test with
      =pytest --runxfail -q <nodeid>= (or temporarily remove the marker in the
      working tree) and confirm it fails at the intended assertion, not on an
      import, fixture, or typo.  Record that reason in the commit message or
      stage log.

      test green, and run =make check=.

      current behavior and pass from the start.  Commit them before the
      refactor and keep them green.

      plan says the behavior changes.  Make that a separate =test:= commit with
      the reason.

      this plan and the public CLI contract, not =src/sink=.

   XPASS and fails the suite, forcing the marker to be removed.

   *Applicability*: this applies to every behavior change or bug fix from
   Stage 3 through Stage 10, and to Stage 11 if it is ever resumed.  Pure
   documentation, CI YAML, formatting, dependency bumps, and type-only changes

* Stage 5 - Typed config and composition root                                   :stage_5:
** Goal
Replace the mutable global =config= and =Dict2obj= with immutable
dataclasses, a pure loader, and a single injected =Runtime=.

** The problem
The current =Configuration= object is the locator (=find_config=), the
loader (=load_config=), the data store (=data=, =project_root=), and a
process-wide singleton.  It exists in a half-initialized state before
=load_config()= runs, so every consumer must know the call order.  The
circular case — "I need info to build the config, but I need the config to
get the info" — comes from mixing *bootstrap inputs* with
*config-derived values*.

** Principle: bootstrap inputs are not config values
Only these are available before any config is read:
- the working directory (=cwd=);
- CLI arguments (=--color=, and a path selector if one is ever added);
- environment variables (=HOME=, =XDG_*=, =${ENV_VAR}=);
- stdout/stderr, for the console.

Everything else is derived: config path -> project root -> servers ->
SSH keys, databases, URLs.  Never source a bootstrap input from the
config.  Resolve relative paths against the config file's parent
(=path.parent=), never against a value inside the config.

If a real cycle remains (for example, a profile name stored in the config
that selects which config to load), move the selector to argv/env or do a
deliberately documented two-pass read.  Do not make two-pass the default.

* Definition of done
  - =uv sync=, =make check=, =make ci=, and =make build= pass from a clean
    clone.
  - =ruff check=, =ruff format --check=, =ty check=, and =pytest= are clean;
    branch coverage is >= 90%.
  - No =shell=True=, no =Dict2obj=, no global config, no naive datetimes, no
    =os.chdir=.
  - No known High-severity bug or security finding remains.
  - =-h=, =--help=, =--version=, =--config=, =--completions=, and =--color=
    behave as specified outside a project.
  - Every command builds one command object.  By default it uses the tool's
    native dry-run when one exists (=rsync=) and prints only otherwise.
    =--real= prints and executes the real variant.  Copy-pasting either
    printed command reproduces that mode's action.
  - README, docs, man page, AGENTS.md, and TODO.org match the shipped behavior.
  - The repository history is clean of secrets and CI enforces it.
