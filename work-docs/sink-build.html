Sink, rebuilt from the specification

Sink is a Python command-line tool that moves website files and MySQL databases between a local project and remote Linux servers through rsync, ssh, mysqldump, and mysql. Its defining behavior: it prints the exact shell command for every action, and the printed command is what runs. Dry-run is the default.

✓
Core contract, memorized first. Build one command object per action before doing anything. Render it to valid POSIX shell. Print it. What you are building

A stateless, config-driven CLI for one project and many servers. It is a transparent orchestrator, not a daemon, not a deployment system, not a GUI.

What makes it Sink

Command transparency, safe dry-run defaults, one sink.yaml, timestamped DB pulls with LATEST-* links, out-of-band database passwords, and a read-only check command.

What it is not

It does not deploy releases, delete remote files, run continuous sync, manage migrations, preserve full POSIX metadata, or support Windows or non-Linux remotes as first-class targets.

01

What Sink is

Sink is a developer-facing front end for the small set of shell tools that almost every self-managed website already requires. It turns remembered incantations into a checked, repeatable, inspectable workflow.

The problem

  • Every environment has a different host, user, key, port, root, and database.
  • rsync flags and SSH quoting are easy to get wrong, especially with spaces and special characters.
  • Database passwords leak into shell history, ps, logs, and screenshots when typed on the command line.
  • Pulling a database produces a differently named dump every time, with no obvious “latest”.
  • Destructive operations are one typo away, and dry-run is usually an afterthought.

The answer

  • One sink.yaml per project, discovered by walking up from the current directory.
  • Commands that print the exact command first and execute the same thing.
  • Dry-run by default; --real explicitly opts in to side effects.
  • Database credentials passed through the environment or a temporary remote 0600 option file, never argv.
  • A small, stable vocabulary: file, db, diff, ssh, action, check, info, misc.

The product contract

  1. Transparency. The rendered shell command is the product. Every action goes through one command object that owns both render(real) and execute(real).
  2. Safe default. No destructive operation runs without --real. rsync is the only tool executed in dry-run mode, using its native --dry-run; every other tool is printed and not spawned.
  3. One config. sink.yaml is the only persistent state. There is no database, daemon, server component, or telemetry.
  4. One project root. Local paths must stay inside project.root; a path outside it is rejected rather than turned into a remote absolute path.
  5. Explicit confirmation for warned servers. warn: yes asks before a real file put or database put.
  6. Secrets out of band. Passwords never appear in rendered commands, argv, logs, or success output. They are redacted by default from machine output.
  7. Honest failure. A failed command exits non-zero, reports the real stderr, and does not print a success label. A failed DB pull deletes the truncated dump and leaves LATEST-* untouched.

Design principles to preserve

Thin, not clever

Sink wraps real tools. It does not reimplement rsync, SSH, or MySQL semantics, and it does not hide the command it runs.

Explicit over automatic

No background sync, no watcher, no deploy hooks. The user runs a command; Sink shows what it will do; the user opts in with --real.

One representation

An Argv, RemoteCommand, or Pipeline object is the single source of truth for both display and execution.

Fail closed on paths

Reject paths outside project.root, reject bad gzip files, reject traversal in tags, sanitize names used in filenames.

Do not trust color

Every status carries a word as well as a color: [Success], [Warning], [Error], [✓], [✗].

Boring dependencies

Click for parsing, Rich for human output, PyYAML for config, stdlib for execution. No shell framework, no ORM, no deploy engine.

02

Good for / not good for

Position Sink honestly. It is excellent at a narrow job and deliberately poor at several adjacent jobs. An AI rebuilding it must preserve the scope, not “improve” it into a deployment platform.

Good for

  • Explicit, auditable file sync from a local project root to a remote document root, and back.
  • Database snapshots before risky changes: timestamped, gzipped, never overwriting an existing dump, with a stable LATEST-<server>.sql.gz symlink.
  • Small teams and solo developers who want a checked, repeatable alternative to hand-typed rsync/mysqldump commands.
  • Multiple environments in one file: dev, stage, prod; different SSH users, keys, ports, roots, and databases.
  • Dry-run-first workflows. Every command can be inspected before it touches a server.
  • Copy-paste command transparency for debugging, documentation, and teaching.
  • Local MAMP, Lando, and DDEV database pull/push as first-class variants.
  • Credential hygiene without a secret manager: env expansion in YAML and out-of-band MySQL passwords.
  • Read-only environment checks for SSH, root directory, MySQL credentials, and HTTPS/TLS URLs.
  • Scripting via -qq (exit code only) and misc api (JSON).
  • Restricted use cases: one project root, Linux remote servers, key-based SSH, MySQL/MariaDB clients.

Not good for

  • Deployment orchestration. No releases, build pipelines, atomic symlink switches, rollbacks, or multi-host rollout. The deploy command was removed in 0.3.0 and must not be reintroduced.
  • Continuous or bidirectional sync. No watch mode, no daemon, no conflict resolution, no --delete, no mirroring.
  • Database migrations or schema management. It dumps and restores whole databases; it does not version them.
  • Non-MySQL databases. No PostgreSQL, SQLite, MongoDB, or Redis support.
  • Windows local workstations. The implementation assumes POSIX paths, a POSIX shell, rsync, ssh, gzip, and Unix permissions. Linux and macOS are the supported local platforms.
  • Non-Linux remote servers. Remote behavior is tested on Ubuntu LTS; macOS/BSD remote rsync and shell behavior are untested.
  • GUI-only users. This is a terminal tool. Compare with FileZilla, TablePlus, or Cyberduck if a GUI is required.
  • Team secret distribution. It reads secrets from environment variables or plain YAML; it is not a vault and does not encrypt config.
  • Servers without rsync, ssh, and MySQL clients, SFTP-only hosts, restricted shells, or control panels that block SSH.
  • Preserving ownership, groups, modes, and timestamps by default. rsync is invoked without --archive, --perms, or --times. Ownership changes are opt-in and may require privileges.
  • Large fleets or multi-tenant management. One project per config; no inventory, roles, or global policy engine.
  • Password-only SSH authentication as a managed feature. Key-based SSH is the supported path. The ssh.password field is loaded for settings display, not used to authenticate.

Architecture and data flow

The implementation is a small layered Python package. The important structural rule is that only the runtime loads configuration, and only the shell module spawns processes. Preserve those boundaries; the test suite enforces them.

Request flow

  1. Click parses global options, configures ui, optionally configures logging, and creates a Runtime in ctx.obj.
  2. The command asks rt.config. The runtime walks up from cwd for sink.yaml, loads it lazily, caches it, and emits any loader warnings once.
  3. The command builds a feature object: Transfer, DB, SSH, Actions, or TestConfig.
  4. The feature builds an Argv, RemoteCommand, or Pipeline before acting.
  5. shell.run renders the command, prints it unless quiet, and executes only when the mode permits.
  6. ui prints command output, a success label, a warning, or an error. Expected failures raise a typed SinkError; the CLI group catches it and exits 1.

Dependency boundaries

These are enforced with import-linter; a recreation should preserve them or an equivalent architecture test.

  • Layers: sink.cli → sink.runtime → sink.config.loader → sink.config.models.
  • Only runtime loads config. The feature modules (actions, applications, check, credentials, db, init, rsync, shell, ssh, ui) must not import sink.config.loader.
  • Models are pure. sink.config.models must not import the loader or runtime.
  • No global config singleton. No Dict2obj; no load_config() global; commands receive a runtime through ctx.obj.
  • One execution layer. Only shell.py calls subprocess; no shell=True anywhere.

Platform support

Local workstation

  • Linux: primary and fully supported.
  • macOS: supported with Homebrew rsync; the platform-specific rsync_binary.osx path exists for this.
  • Windows: not supported. No PowerShell/cmd handling, no POSIX path translation, no native rsync assumption.
  • Completions: bash 4.4+ only. The generated script checks BASH_VERSINFO and declines to load on older bash.

Remote server

  • Linux: the tested target (Ubuntu 20.04 through 26.04).
  • macOS/BSD remote: untested; rsync and shell differences are not modeled.
  • Requirements: SSH server, rsync, a POSIX shell, gzip/gunzip, and MySQL client tools for DB commands.
  • Authentication: prefer keys. Host keys should be pre-trusted because several probes use StrictHostKeyChecking=yes.
  • Access: the SSH user must be able to write the remote root for file puts. Ownership changes need privilege; Sink does not inject sudo into rsync.

Missing-tool and missing-value behavior

  • Missing sink.yaml: NotInProject with “You are not in a project…”.
  • Missing server root for file transfer: TransferError("Server has no root (name).").
  • Missing SSH entry for a server: UI error or CommandError depending on path; no transfer is built.
  • Missing database entry: CommandError("Server X has no database configured").
  • Missing pulls_dir: CommandError("project.pulls_dir is not configured").
  • Missing configured SSH key: loader warning, key becomes None, and commands still render without -i so they can be inspected.
  • Missing binary: the command is still rendered; the OS produces the failure in real mode. check explicitly reports missing rsync_binary.
  • Missing env var referenced by ${NAME}: configuration error at load time; no command runs.

sink.yaml reference

sink.yaml is a YAML mapping with exactly two top-level sections: project and servers. It is discovered by walking up from the current working directory, like .git discovery.

Discovery and loading

  1. Resolve the current directory. Check sink.yaml in it, then each parent, stopping at the filesystem root.
  2. If none is found, raise NotInProject. sink --config prints the discovered absolute path without parsing the file.
  3. Use yaml.safe_load. An empty document, a non-mapping top level, or invalid YAML is a ConfigError that includes the path.
  4. Recursively expand ${NAME} in every string value, including list items and mapping keys’ values. A missing variable aborts configuration with environment variable "${NAME}" is not set.
  5. Validate types, resolve local paths, resolve SSH keys, collect unknown keys, collect non-fatal warnings, then freeze into immutable models.
  6. Exactly zero or one server may have default: yes. Two or more is a configuration error.
  7. Normal commands ignore unknown keys. sink check prints each unknown key as a warning.
  8. Loader warnings (for example a missing SSH key) are printed once, when the runtime first loads the config.
!
YAML type strictness. String fields reject unquoted YAML numbers and booleans. password: 1234 is an error; write password: "1234". Boolean fields accept real YAML booleans and the strings yes/no/true/false/on/off/1/0 (case-insensitive, empty means false). Integer fields accept integer-like strings.

Execution model

This is the heart of the app. Implement it before the features, and implement the features only through it.

Command protocol

Each command object provides:

MethodContract
argv_for(real)Return the local argv for the selected mode. Pipelines have no single argv and raise TypeError.
render(real)Return valid POSIX shell text equivalent to the selected mode. Use shlex.join / shlex.quote.
can_execute(real)Whether the selected mode may spawn a process. Argv: real or has a native dry-run flag. RemoteCommand and Pipeline: real only.
execute(real, …)Run exactly the selected variant, optionally capturing stdout/stderr.

Argv

A frozen dataclass holding argv: tuple[str, ...], optional dry_run_flag: str | None, and env_refs: tuple[str, ...]. The argv must contain at least the program. In dry-run mode, the flag is inserted immediately after the program name: (argv[0], flag, *argv[1:]). Rendering with env refs prefixes NAME="${NAME}" for each one. This is how MYSQL_PWD appears in a rendered local DB command without exposing its value.

RemoteCommand

Holds a local ssh argv plus one remote shell fragment. Rendering appends the quoted fragment as one argument. Execution passes the exact same fragment to the remote shell. Remote commands have no native dry-run, so default mode prints only.

Pipeline

Holds stages (Command objects), an optional stdout_path, an optional stderr_path, and stderr_devnull. Rendering joins stages with | and adds > file / 2> file / 2>/dev/null. Execution starts a Popen chain, closes the parent's copy of each intermediate pipe so the reader sees EOF, gives every stage the same stderr sink (a temporary file when capturing), waits for all stages, and terminates/reaps on interruption. The pipeline return code is the first non-zero stage, otherwise the last stage. This prevents a failing producer such as mysqldump | gzip from being hidden by a successful consumer.

Rendering and quoting rules

  • Use argv lists end to end. Never use shell=True.
  • Render with shlex.join(argv). A rendered command must reproduce the executed argv when pasted into a POSIX shell.
  • Keep each rendered command on one logical line. Do not insert backslash-newline continuations; wrapping inside a quoted argument changes the command.
  • Quote remote fragments as one argument. The fragment itself may contain shell syntax and is executed by the remote shell, not the local shell.
  • Absolute paths are used where the shell would otherwise resolve relative to a different directory.
  • Secrets are never placed in argv. Environment references are displayed as NAME="${NAME}"; credential files are displayed as --defaults-extra-file=/tmp/sink-mysql-….cnf.
  • Command display is + <command> in yellow/dim on stdout. Tool output follows unstyled. Success is a labeled line, not just color.

  [-C]                              # compress, when requested

Error handling

  • SinkError is the base of expected failures: ConfigError, CommandError, TransferError, NotFoundError, NoDefaultServer, UnknownServer, NotInProject.
  • The CLI group catches SinkError, prints ErrorType: message via ui.error, and returns 1. No traceback for expected failures.
  • Unexpected exceptions are not caught; Click/Python behavior applies.
  • ui.error exits 1 by default; some call sites pass exit=False to print and then decide.
  • On a failed command, print the real stderr, never a success label, and exit non-zero.

File transfers (rsync)

Transfers are one-shot rsync runs with explicit flags. They are not mirrors: Sink never passes --delete, and it never runs a daemon.

Path mapping

For a local path, resolve it and compute its path relative to project.root. The remote path is server.root / relative. If the local path is outside the project root, raise TransferError instead of turning it into a remote absolute path. A server without root is also an error.

local:  <project.root>/sub/file.txt
remote: <server.root>/sub/file.txt

Exact rsync command

Template — argument order matters
rsync
  [--dry-run]                                  # inserted at position 1 by Argv
  [--rsh "ssh [-p PORT] [-i KEY]"]             # one argument
  [--group] [--owner] [--chown=USER:GROUP]     # put only, when group/user configured
  [EXTRA_FLAGS ...]                            # from --extra-flags, shlex.split
  --itemize-changes --links --compress
  --checksum
  [--quiet]                                    # silent or quiet
  [--verbose]
  [--recursive]                                # directory/whole-project transfers
  --include .env.SERVER
  --include robots.txt.SERVER
  --include .htaccess.SERVER
  [--exclude PATTERN ...]                      # directory transfers only
  SOURCE DESTINATION
  • Always: --itemize-changes, --links, --compress, --checksum.
  • Not passed: --archive, --perms, --times, --owner/--group unless configured, --delete, --rsync-path.
  • Includes: environment/robots/htaccess files for the target server are included before excludes. rsync’s first-match-wins rule means these specific files win over broad excludes.
  • Excludes: project and server excludes are merged, deduplicated, sorted, and only added for directory transfers. Single-file transfers do not get excludes.
  • Directory put: local path gets a trailing slash; remote path does not. Contents of the local directory are copied into the remote directory.
  • Directory pull: remote path gets a trailing slash; contents are copied into the local directory.
  • Ownership: adding --group/--owner/--chown assumes privileges. The tool does not automatically use sudo rsync.

Put, pull, diff

ActionSource → destinationNotes
putLOCAL → USER@HOST:REMOTEDirectories append / to local and add --recursive.
pullUSER@HOST:REMOTE → LOCALDirectories append / to remote and add --recursive.
diffUSER@HOST:REMOTE → TEMPDIRNo native dry-run. For directories, --compare-dest=<local> is added; remote gets a trailing slash.

Failure and cleanup

  • If rsync returns non-zero, print its stderr and exit 1. Do not print a success label.
  • On an interrupted single-file pull, remove leftover .NAME.XXXXXX temporary files beside the local destination, then re-raise.
  • For a warned server, a real put asks “WARNING: You are about to overwrite the … files, continue?”. Declining returns without executing and without an error.
  • Success labels: [Success] SERVER: upload complete or download complete; dry-run uses [Success (DRY RUN)].

Database engine (MySQL)

Database work is the most safety-sensitive part of Sink. Implement pull and put as explicit pipelines with strict validation, collision avoidance, and out-of-band credentials.

Dump names and the LATEST link

  • Destination: pulls_dir/{project}-{server}-{YY-MM-DD_HH-MM-SS}[-{tag}].sql.gz.
  • Local time, timezone-aware. The clock is read with datetime.now(datetime.UTC).astimezone().
  • Project and server names are reduced to one safe filename component: runs outside [A-Za-z0-9._-] become -, leading/trailing dashes stripped, empty becomes x.
  • Tags must match [A-Za-z0-9._-]+ and must not be . or ... Invalid tags are a CommandError before any work.
  • If the name exists, append -2, -3, … before the suffixes, up to 999. Never overwrite.
  • On a successful local pull, atomically replace LATEST-{safe-server}.sql.gz with a relative symlink ./{filename}. Build at .LATEST-….{pid}.tmp, then replace(); clean up the temp name in a finally.
  • On failure, delete the truncated local dump (and a possible .gz sibling), never touch LATEST-*, print the real stderr, and exit 1.

Put validation order

  1. Require SQL_GZ in the CLI; Click also checks that it exists.
  2. Read the first two bytes; require 0x1f 0x8b. Reject anything else before touching the network.
  3. Require at least one configured database; only the first is used.
  4. If warn: yes and --real, ask for confirmation. Declining exits 0 without executing.
  5. Check that the local file exists (again) or, for an internal remote source, that the remote file exists.
  6. Build and run the pipeline.

Credential handling

Remote

  1. Create a random remote path: tempfile.gettempdir()/sink-mysql-<uuid hex>.cnf.
  2. Body: [client], then user=, password=, host=, port= as configured.
  3. Every value is double-quoted; backslash and double quote are escaped. MySQL treats # as a comment even mid-line, so quoting is mandatory.
  4. Stage over SSH stdin: umask 077; cat > PATH. The password never appears in argv.
  5. Prefix the real command with trap 'rm -f PATH' EXIT; ….
  6. Afterward, run a separate rm -f PATH as a fallback cleanup.
  7. Rendered commands show the path, never the password.

Local / MAMP

  1. Copy os.environ and set MYSQL_PWD to the configured password.
  2. Render the command with an env reference: MYSQL_PWD="${MYSQL_PWD}".
  3. Pass the same environment to the child process.
  4. Do not add --password or -p to argv.
!
Redaction. Error output from DB commands is passed through ui.redact with the configured database password(s). Report stderr but never echo the secret. pv --numeric writes progress numbers to stderr; filter purely numeric lines out of failure reports.

SSH and actions

sink ssh

  • Resolve the server. If USER is supplied, select the SSH entry with that name; invalid names are an error. Otherwise use the first SSH entry.
  • If the server has a root, the remote fragment is cd <quoted root>; bash. Otherwise it is empty and the shell starts in the login home.
  • Build a tty SSH command (-t) without batch mode, so interactive authentication and host-key prompts can work.
  • Default: print the command. --real: execute it with capture=False so the terminal is interactive.

sink check

A read-only diagnostic command that always runs its probes. It is the one exception to dry-run-by-default, because none of its operations modify anything.

Execution order

  1. Print a warning for every unknown config key.
  2. Print a “Local dirs” heading and a table of pulls_dir and rsync_binary. cache_dir and log_dir are intentionally not listed.

  4. For each SSH entry: require username and server; run exit; if successful, run cd <root>; if that succeeds, probe every configured database.
  5. For each URL: perform an HTTPS/TLS reachability probe and print the result.

Redaction layers

Commands

Secrets are structurally absent from argv; rendered commands show env references or credential-file paths.

Errors

ui.error(..., secrets=…) replaces known database passwords before printing.

Machine output

misc api masks sensitive keys; misc settings replaces every configured password.

Threat notes and non-goals

  • Sink trusts sink.yaml, the local machine, and the remote shell. It is not a sandbox or a policy engine.
  • It does not protect against a compromised remote host, a malicious rsync binary, or secrets in the user's environment.
  • It does not encrypt sink.yaml. Use ${ENV_VAR} and keep the file out of version control if it contains secrets.
  • It does not implement password-based SSH auth, SSH agent forwarding, or jump hosts explicitly; ssh's own config can supply those.
  • It does not verify gzip integrity beyond the magic bytes; a truncated but valid-magic file could pass the initial check.
  • It does not run a checksum of the DB after restore.
  • It does not protect against a local attacker who can read the environment or the process memory.

Edge cases and quirks

These are easy to miss and often distinguish a faithful recreation from a plausible one.

Behavioral quirks to preserve (or explicitly change)
  • sink check exits 0 even when probes fail; failures are red lines, not a non-zero aggregate. Preserve for parity or document a deliberate change.
  • sink file put index.html treats a single non-server token as a filename on the default server. A token that happens to equal a server name means “whole project on that server”.
  • Excludes apply only to directory transfers. A single-file put/pull gets includes but no excludes.
  • diff default mode prints a [Success (DRY RUN)] … download complete line even though nothing was downloaded. The rsync command is printed, then the git command is printed.
  • Local actions do not use a shell. A local action containing | or > will be split into argv literals, not interpreted. Remote actions do use the remote shell.
  • ssh.password is for settings output only. It is never used to authenticate.
  • The first SSH entry is used by rsync, DB, and actions. Only sink ssh can select another by name.
  • The first database is used by sink db; sink check probes every database.
  • db pull into a standard remote path requires pulls_dir to exist; the code checks it. Lando/DDEV paths do not perform the same existence check.
  • db put validates the gzip magic before checking the remote. A non-gzip file fails locally.
  • db put with warn: yes prompts only in real mode. Dry-run prints the pipeline without a prompt.
  • A declined warn confirmation exits 0 and may still have printed the command in real mode before asking. No side effect occurs.
  • LATEST-* is a relative symlink ./filename, replaced atomically. It is created only for local pulls, not dump_remote.
  • Dump names are sanitized, not rejected. A project named ../x becomes a safe component rather than escaping.
  • Tags are stricter than names: invalid characters are rejected, not sanitized.
  • misc api redacts by key name, not by value content. A secret stored under a non-sensitive key is printed.
  • misc settings redacts by replacing known password strings anywhere in the output.
  • --config finds the file but does not parse it, so it works with invalid YAML.
  • --completions writes outside the project and requires no project.
  • check --required still loads the project (so it needs a config) but only prints the version command.
  • Server-name filters for check are lowercased; server keys are otherwise case-sensitive.
  • Unknown keys are ignored by normal commands but visible in check and misc api.
  • Legacy keys deploy_root, automatic, servername, and databases are accepted.
  • Python 3.15 syntax uses unparenthesized multi-exception handlers (except TypeError, ValueError:); add parentheses if targeting older Python.
  • rsync --rsh is one argument containing ssh -p … -i …. Do not pass a separate -e; it would silently win.
  • For chown, rsync needs --group/--owner alongside --chown; Sink adds them. It does not set --rsync-path="sudo rsync".
  • Command display uses soft_wrap so a long command stays one copy-pasteable line; it may visually overflow.
  • -qq suppresses Sink's own command output, success lines, warnings, and errors; Click usage errors (unknown option, bad argument) can still be printed by Click. The exit code remains the reliable signal.
Explicit non-goals (do not add these)
  • Do not add a deploy command, release directory, rollback, or build system.
  • Do not add a single command. Use file put/pull.
  • Do not add a vm group or Vagrantfile.
  • Do not add a global config singleton, Dict2obj, or shell=True.
  • Do not add dynamic server-name completion or a Python-at-tab-time completion script.
  • Do not add a GUI, web server, daemon, watcher, or database.
  • Do not add a --delete flag as a convenience; it violates the safety scope.
  • Do not add non-MySQL database support without an explicit product decision.
  • Do not add automatic deployment on push or any CI integration inside the app.

# Sink recreation brief

Build `sink`, a Python 3.15 Click CLI that moves website files and MySQL
databases between one local project and remote Linux servers.

## Non-negotiable product behavior
- Print every shell command you will run, in copy-pasteable POSIX shell.
- The printed command IS the executed command; no second construction path.
- Dry-run is the default. With no `--real`, execute only rsync's native
  `--dry-run`; print all other commands and do not spawn them.
- `--real` / `-r` prints and executes the real command.
- `sink check` is the exception: read-only probes always run, no `--real`.
- Use argv lists, never `shell=True`. Build pipes with a Popen chain.
- Never put a password in argv, a rendered command, or a log.
- Reject local paths outside `project.root`.
- A failed command exits non-zero and prints no success label.

## Stack
- Python >= 3.15, uv, hatchling, src layout, pyproject.toml only.
- Runtime deps: click>=8.5, PyYAML>=6.0.4, rich>=15.
- Dev: pytest, pytest-cov, ruff, ty, import-linter, Sphinx/MyST/Furo.
- Entry point: `sink = "sink.cli:main"`; version single-sourced; GPL-2.0-only.

## Project layout
src/sink/{__init__,__main__,runtime,errors,shell,ui,rsync,db,ssh,actions,
check,credentials,applications,init,completions,logging}.py
src/sink/config/{models,loader}.py
src/sink/cli/{__init__,file,diff,db,ssh,action,check,info,misc}.py
tests/ with stub binaries and golden fixtures; tests/integration for Docker.

## Config
`sink.yaml` is found by walking up from cwd. Top level: `project` (required),
`servers` (optional map). Expand `${ENV}` in all strings; missing env var is a
config error. Resolve project paths relative to the config file. Freeze into
immutable dataclasses. Only Runtime loads config.
project keys: name, root(required), pulls_dir, cache_dir, log_dir,
rsync_binary, difftool, exclude, actions, pv, mysqlpump, note.
server keys: root, type(lando|ddev), warn, default, automatic(legacy),
group, user, ssh[], mysql[]/databases[], urls[], actions, exclude, mamp,
hosting, control_panel, note.
ssh keys: name, username, password(settings only), server, key, port, note.
mysql keys: db, username, password, hostname, port(3306), skip_secure_auth, note.
urls keys: url, admin_url, username, password, htusername, htpassword, note.
Unknown keys warn in `check`, are ignored otherwise. Legacy deploy_root,
automatic, servername, databases are accepted.

## Commands
- sink file {put|pull} [SERVER] [FILENAME] [-r] [--extra-flags] [--silent]
  One non-server token = filename on default server. Dir transfers recursive.
- sink diff SERVER [FILENAME] [-i] [-d] [-w word|letter] [-r]
  Download to temp, then git diff (or project.difftool). Exit 1 when different.
- sink db {put|pull} SERVER [SQL_GZ] [-t TAG] [-r] [--filename-only]
  Pull to pulls_dir as project-server-YY-MM-DD_HH-MM-SS[-tag].sql.gz; never
  overwrite; update LATEST-<server>.sql.gz atomically on success. Put validates
  gzip magic first; warn asks before real overwrite. Only the first DB is used.
- sink ssh SERVER [USER] [-r]  print, or open `ssh -t ... 'cd ROOT; bash'`.
- sink action SERVER [NAME] [-r]  `local` uses project.actions. List or run.
- sink check [SERVERS]... [-R] [--insecure]  always runs read-only probes.
- sink info [-v|-e]  view or edit sink.yaml with YAML validation and retry.
- sink misc api KEYS... [--show-secrets]  JSON only, redacted by key name.
- sink misc settings [mysql|filezilla|nautilus|dbeaver] [--show-secrets].
- sink misc pack  print a git-based tar command; do not run it.
- sink misc init [SERVERS]...  print starter YAML.
Global: -q/-qq, -s, --silent, -v, --color auto|always|never, --config,
--completions, --version, -h/--help.

## Exact transfer command
rsync [--dry-run] [--rsh "ssh [-p P] [-i K]"]
  [--group] [--owner] [--chown=U:G] [EXTRA] --itemize-changes --links
  --compress --checksum [--quiet] [--verbose] [--recursive]
  --include .env.SERVER --include robots.txt.SERVER --include .htaccess.SERVER
  [--exclude PATTERN ...] SRC DST
Remote path = server.root / local path relative to project.root.
Directory put: local trailing slash. Directory pull: remote trailing slash.
Never pass --delete. Excludes only for directory transfers.

## Database specifics
- Remote creds: temp /tmp/sink-mysql-<uuid>.cnf, [client] user/password/host/port,
  values double-quoted with escapes, staged over ssh stdin with umask 077,
  command wrapped in `trap 'rm -f PATH' EXIT`, fallback cleanup.
- Local/MAMP creds: MYSQL_PWD in child env, rendered as MYSQL_PWD="${MYSQL_PWD}".
- Dump: mysqldump --single-transaction --triggers --events --routines
  --no-tablespaces DB, or mysqlpump --watch-progress DB if configured.
- Pull remote: ssh -C -T ... 'trap ...; mysqldump ...' | gzip -c > FILE.
- Put remote: (cat|pv --numeric) FILE | ssh -T ... 'trap ...; gunzip -c | mysql ... DB'.
- MAMP: <mamp>/mysqldump and <mamp>/mysql locally.
- Lando: lando db-export without .gz / lando db-import FILE.
- DDEV: ddev export-db --gzip --file=FILE / ddev import-db --progress --src=FILE.
- On failure delete truncated local dump, leave LATEST untouched, exit 1.

## Check
Local: pulls_dir, rsync_binary. Per server: root, warn; ssh `exit`;
`cd ROOT`; each DB `mysql --defaults-extra-file=... DB --execute=exit`;
each URL via urllib with TLS verify (or --insecure). Batch SSH uses
BatchMode=yes and StrictHostKeyChecking=yes. `--required` prints a
version-reporting bash loop and runs nothing.

## Quality
Ruff format/lint, ty, import-linter boundaries, pytest with branch coverage
>= 90%, docstrings on every module/callable, gitleaks pre-commit, Docker
integration on Ubuntu 20.04 and 26.04. Golden tests pin rendered commands.

## Do not add
deploy, single, vm, shell=True, global config singleton, watcher/daemon,
--delete, GUI, non-MySQL, password SSH auth management.
