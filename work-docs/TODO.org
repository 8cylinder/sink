** TODO Harden database credential handling
   Current method: a random =0600= MySQL option file is staged over SSH
   stdin, referenced with =--defaults-extra-file=, quoted/escaped, and
   removed by a remote =EXIT= trap plus a fallback cleanup command.

   Remaining options, roughly strongest first:
   - [ ] Support passwordless =auth_socket= / =unix_socket= for databases
         on the SSH host.  Skip credential staging for those entries.
   - [ ] Support =mysql_config_editor --login-path= as an alternative to a
         plaintext password.
   - [ ] Support a persistent =0600= file passed with =--defaults-file=.
   - [ ] Consider IAM database auth, TLS client certificates, or a secrets
         manager for managed databases.
   - [ ] Decide how these map onto =DatabaseConfig= without pre-empting the
         deferred schema v2 work (D6).
   - [ ] =db pull= / =db push= use =databases[0]=.  Add a way to select an
         entry by username or index when several are configured.

** MAYBE Custom db pull filename
   Allow a token-based name:

   | token | field       |
   |-------+-------------|
   | =%u=    | user        |
   | =%n=    | db name     |
   | =%s=    | server name |
   | =%d=    | short date  |
   | =%D=    | long date   |
   | =%t=    | tag         |

   Examples:
   - =%n-%s-%d= -> =dbname-servername-20-01-30.sql.gz=
   - =%n--%s:u--%D= -> =dbname--SERVERNAME--20-01-30-10:30:15.sql.gz=
** MAYBE Pre-pull before put
   List files to pull before putting files.  Useful for project config
   files, such as a Craft =project.yaml=, that should not be overwritten
   by the local copy.
** MAYBE Option to upload a bashrc file and execute it when sshing
   For locked-down servers that do not allow editing =.bashrc=.
